Everything the API does is plain HTTPS with a bearer key, so you never need a library. Client libraries take
care of the plumbing you would otherwise write yourself.

| What | For | Status |
| --- | --- | --- |
| **TypeScript client** (`@clinikehr/api`) | Node.js and server-side TypeScript | **Available now.** [npm](https://www.npmjs.com/package/@clinikehr/api) · [Source](https://github.com/clinikehr/sdk-typescript) |
| **Python client** (`clinikehr`) | Python 3.11+ services and scripts | **Available now.** [PyPI](https://pypi.org/project/clinikehr/) · [Source](https://github.com/clinikehr/sdk-python) |
| **Postman collection** | Trying a request by hand | **Available now.** [Download it](/downloads/clinikehr-ehr-api.postman_collection.json). |

## Install the TypeScript client

```bash
npm install @clinikehr/api
```

```ts
import { createClient } from "@clinikehr/api";

const client = createClient({ apiKey: process.env.CLINIKEHR_API_KEY! });
const me = await client.GET("/v1/me");
```

It calls `https://api.clinikehr.com/v1` by default. Start with a **test** key from the
[developer portal](https://developer.clinikehr.com) — it reaches only your sandbox. Call the API from your server:
the client refuses to run in a web browser, whatever the key.

**[Read the full TypeScript client guide →](/typescript-sdk)** — calls, idempotent writes, retries, errors, paging,
FHIR and webhooks.

Each published version is built from its public source by GitHub Actions and carries a signed provenance
statement, so you can confirm what you installed with `npm audit signatures`.

## Install the Python client

```bash
pip install clinikehr
```

```python
import os

import clinikehr
from clinikehr._generated.api.me import get_me

client = clinikehr.create_client(os.environ["CLINIKEHR_API_KEY"])
me = clinikehr.raise_for_response(get_me.sync_detailed(client=client))
```

It also calls `https://api.clinikehr.com/v1` by default, and needs Python 3.11 or later. Use a **test** key from the
[developer portal](https://developer.clinikehr.com) to begin, and keep your key on your server: unlike the TypeScript
client, the Python client has no way to tell that it has been put in front of a browser.

**[Read the full Python client guide →](/python-sdk)** — calls, idempotent writes, retries, errors, paging, FHIR and
webhooks.

Each published version is published from its public source by GitHub Actions using PyPI trusted publishing, and PyPI
shows a signed attestation for each file on that file's page.

<Warning>
  Install only the package named `clinikehr` from [PyPI](https://pypi.org/project/clinikehr/), and only
  `@clinikehr/api` from npm. Do not install a package with a similar name, or either of these names from anyone
  else's account or mirror: they are ours alone.
</Warning>

## What the libraries do

Both are thin. They call the same endpoints this documentation describes, and add the parts that are
easy to get wrong:

- sending your key, and keeping it out of a browser;
- a fresh `Idempotency-Key` on every write, **reused across retries** so a retry cannot create a
  second record — see [Retries and duplicates](/retries-and-idempotency);
- retrying a failed or rate-limited request with a sensible delay — see [Rate limits](/rate-limits);
- walking a paged list for you — see [Pagination](/pagination);
- typed errors that carry the `code` and `request_id` — see [Errors](/errors);
- checking a webhook's signature — see [Verifying a webhook's signature](/verifying-webhook-signatures);
- asking for FHIR instead of JSON — see [FHIR R4](/fhir).

## The Postman collection

The collection has one request for every endpoint, grouped the way this reference groups them.
To use it:

1. **Get the collection.** [Download the collection](/downloads/clinikehr-ehr-api.postman_collection.json)
   (one JSON file). It is kept in step with this reference, so download it again when the API changes.
2. In Postman, choose **Import** and select the file.
3. Open the collection's **Variables** tab. `baseUrl` is already `https://api.clinikehr.com/v1`.
   Set `bearerToken` to your key. Use a **test** key from the [developer portal](https://developer.clinikehr.com)
   to begin, which reaches only your sandbox.
4. Send the request for `GET /v1/me` first. It tells you which clinic or workspace the key belongs to, and proves
   the key works.

Every request that creates or changes something carries an `Idempotency-Key` header with a fresh
value, so sending it twice by accident does not do it twice. Fill in the path values (such as
`clinic_id`) and the body before you send.

<Note>
  Treat your key like a password. Do not save a live key into a collection you share, and do not
  export a collection with a live key filled in.
</Note>
